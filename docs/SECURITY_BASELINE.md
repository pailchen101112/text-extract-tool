# 应用安全基线与等保三级上线清单

本文件说明当前代码覆盖的应用层控制，以及要达到等保三级测评条件仍需在部署和管理侧完成的事项。它不是测评结论或合规证书。

## 已在代码中实现

| 控制领域 | 实现 |
|---|---|
| 身份唯一性 | 用户名唯一约束，账号启停状态 |
| 口令保护 | BCrypt cost 12；12-64 位，要求大写、小写、数字和特殊字符；禁止包含用户名 |
| 登录失败处理 | 连续 5 次失败锁定 30 分钟；成功登录后清零；管理员可解锁 |
| 凭据生命周期 | 初始/重置密码强制修改；默认 90 天到期后强制修改 |
| 会话控制 | 无状态 JWT，默认 30 分钟过期，不提供长期刷新令牌 |
| 访问控制 | 用户—角色—菜单/权限点 RBAC；前端菜单裁剪；后端方法级强制鉴权 |
| 最小权限 | 附件、检索、五类管理资源分别设置 list/write 权限 |
| 安全审计 | 登录成功/失败、改密、账号解锁以及管理数据增删改写入 `logs/security-audit.log`，保留 180 天 |
| 输入与文件安全 | 扩展名白名单、MIME 嗅探、canonical 路径白名单、大小限制、文本长度限制 |
| 抗滥用 | `/api/**` 按客户端 IP 限流；登录另有账号级失败锁定 |
| Web 安全头 | nosniff、禁止 framing、CSP；CORS 来源显式配置 |
| 错误处理 | 认证 401、越权 403、限流 429；内部异常不向客户端泄露堆栈与数据库细节 |

## 生产上线前必须完成

1. 通过密钥管理系统注入高熵 `APP_JWT_SECRET`，不得使用仓库中的开发默认值，并建立轮换流程。
2. 全链路启用 HTTPS/TLS 1.2+，HTTP 强制跳转 HTTPS；在可信反向代理处设置并清洗客户端 IP 头。
3. 删除或完成初始 `admin` 改密；为日常管理建立具名账号，限制超级管理员使用并定期复核授权。
4. 后端数据库账号改为专用最小权限账号，禁止使用 root；数据库启用传输加密、访问控制与审计。
5. 将安全审计日志发送到集中、只追加、可校时的日志平台，配置登录失败、越权、批量管理操作告警。
6. 使用 Redis/网关替代单实例内存限流，并针对登录接口设置更严格的 IP/账号组合限流。
7. 根据正式数据分级实现公司/部门数据域隔离；当前 RBAC 控制“能否操作功能”，不自动限制同一功能内可见的数据行。
8. 建立备份、恢复演练、漏洞扫描、依赖升级、补丁、恶意代码防范、应急响应与账号定期复核流程。
9. 完成主机加固、网络区域边界、防火墙/WAF/入侵防范、堡垒机、数据库审计及运维双因素认证。
10. 由合格测评机构依据实际定级对象和部署拓扑执行差距分析、整改与正式测评。

## 建议的后续增强

- 接入统一身份平台、MFA 或硬件令牌。
- 使用短期访问令牌 + 可撤销刷新令牌，并在退出、改密、停用账号时立即吊销现有令牌。
- 增加密码历史，阻止最近若干次口令复用。
- 对高风险管理操作增加二次确认、审批或双人复核。
- 将审计事件写入专用审计表或 SIEM，并加入完整性保护与检索页面。
- 增加公司/部门数据权限规则、字段脱敏与导出水印。
